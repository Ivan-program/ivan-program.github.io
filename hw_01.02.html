Главная идея

В embedded-разработке для роботов давно идёт спор: даёт ли C++ дополнительный overhead и стоит ли уходить от C. Отрасль очень инертная, поэтому этот «холивар» будет тянуться ещё много лет.

Спикер показывает, что C++20 позволяет строить абстракции с «нулевой стоимостью» — код становится удобнее, безопаснее и быстрее в разработке, но не проигрывает C по производительности и контролю над ресурсами.

Речь о том, что constexpr, шаблоны, RAII и концепции позволяют перенести часть работы на этап компиляции и убрать накладные расходы, которые раньше считались неизбежной платой за абстракции.

Где это применяется

Продукты Яндекс Роботикс

  • Робот-пикер — захватывает товары, с помощью нейросети определяет, как правильно взять объект, подносит его к ридеру штрихкодов и перекладывает в другую корзину.
  • Робот-инвентаризатор «Спектр» — едет вдоль стеллажей, с помощью камер находит штрихкоды, повреждения упаковки, оценивает плотность заполнения полок.

Ограничения платформы: 1 МБ памяти под код и 240 КБ оперативной памяти.

Архитектура робота

  • Robotic Management System — стратегия и тактика складских операций.
  • Главный CPU — телеметрия, анализ данных, обновление прошивок.
  • Специализированные вычислители — обработка изображений, управление двигателями.

Код пишется и для серверов, и для платформ с GPU, и для микроконтроллеров, которые управляют сенсорами и BLDC-моторами.

Параметры оценки кода

Технические

  • Нормированный performance — производительность относительно максимума платформы.
  • Jitter — разброс времени отклика. Основа системы реального времени.
  • Объём кода и данных — память на платформе сильно ограничена.
  • Ошибки кэш-линии — лишние обращения к системной шине.

Организационные

  • Скорость разработки — как быстро коллега разберётся в абстракциях.
  • Связанность модулей — чтобы не дублировать код.

Тренд: число ядер растёт, а производительность одного ядра — почти нет. Ускорение идёт за счёт сопроцессоров (NPU) и векторизации.

Три класса задач

DSP

Цифровая обработка сигналов — буферизация, фильтрация, частотный анализ данных с датчиков.

RTPS

Real-Time Publish-Subscribe — обмен командами и телеметрией с вышестоящим API в реальном времени.

GeMM

Матричные вычисления — планировщики траекторий, нейросетевой инференс, компьютерное зрение.

Пример 1: табличные методы в DSP

Что это

Табличные методы (LUT, look-up table) — способ заменить сложные вычисления быстрым доступом к заранее рассчитанным значениям. Аналогия — таблицы Брадиса для синусов и косинусов: значения считали вручную и записывали в книжку.

Задача

Есть зашумлённый сигнал с датчика. Нужно отфильтровать высокие частоты и получить гладкую кривую для управления роботом. Используется свёртка функции с фильтром — lowpass-фильтр низких частот.

В C

  • Нет конструкторов — класс нужно инициализировать вручную.
  • Коэффициенты фильтра берутся извне: MATLAB или скрипт.
  • Для приёма данных по DMA используется глобальная структура.

В C++20

  • Коэффициенты генерируются на этапе компиляции через constexpr.
  • Данные попадают сразу в read-only memory.
  • Фильтр оборачивается в шаблон с параметрами: размер, частота отсечения, частота сэмплирования.

Код на C++20

constexpr auto coeffs = make_lowpass<64, 1000, 10000>();

template <int N>
class Filter {
    float buf[N] = {};
public:
    float apply(float x);
};

Код на C

const float coeffs[64] = { 0.001f, 0.002f, /* ... */ };

struct Filter { float buf[64]; int i; };

void filter_init(struct Filter* f) {
    for (int i = 0; i < 64; i++) f->buf[i] = 0;
    f->i = 0;
}

Результат

  • Ускорение примерно в 6 раз за счёт табличного метода.
  • Около 2 раз быстрее по сравнению с библиотекой ETL.
  • Встроенная векторизация даёт ещё 2 раза.

Пример 2: статическое связывание

Что это

Статическое связывание — соединение компонентов программы на этапе компиляции, а не во время выполнения. Компилятор «вшивает» нужные вызовы напрямую, без указателей и виртуальных функций.

Зачем это в роботах

На микроконтроллерах почти нет динамической памяти и нет MMU. Вся память берётся из оперативной, поэтому используется статический аллокатор. Если число объектов заранее неизвестно, в C память приходится выделять вручную. В C++20 компилятор сам посчитает, сколько нужно.

Как реализовано

  • Статическая модель наблюдателя на рекурсивных шаблонах.
  • Единый код для хоста и микроконтроллера через DDS и Micro XRCE-DDS.
  • Без вектора и массива указателей — они дороги по памяти.

Код

template <typename... Obs>
class Subject {
    std::tuple<Obs...> obs;
public:
    void notify(const Event& e) {
        std::apply([&](auto&... o){ (o.on(e), ...); }, obs);
    }
};

Результат

  • Ускорение в 12 раз по сравнению с C-кодом на указателях.
  • Убираются вызовы по указателю и виртуализация.
  • Данные можно расположить в быстрой Core Coupled Memory.

Пример 3: матричное умножение

Что это

GeMM (General Matrix Multiply) — обобщённое матричное умножение. Базовая операция для нейросетей, управления и планирования траекторий.

Термины

  • SIMD — одна инструкция, много данных.
  • NEON — SIMD для ARM.
  • MVE — векторное расширение для микроконтроллеров ARM.
  • AVX-256/512 — векторные расширения Intel.
  • OpenMP — распараллеливание на несколько ядер.
  • Eigen — библиотека линейной алгебры.
  • Кэш-линия — минимальный блок данных, читаемый процессором.

Что видно на графиках

  • Наивное умножение против поблочного, AVX-256/512 и OpenMP. Референс — Eigen.
  • На размере матрицы около 2048 производительность однопоточного векторизованного умножения резко падает — кончаются линии кэша L1–L3.
  • Вариант с OpenMP такого падения не испытывает — у каждого ядра свой кэш.

Код: поблочное умножение

void gemm(const float* A, const float* B, float* C, int N) {
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
            for (int k = 0; k < N; k++)
                C[i*N + j] += A[i*N + k] * B[k*N + j];
}

Выводы

  • Писать branchless-код — требование MISRA и AUTOSAR.
  • Избегать системных вызовов и лишних аллокаций.
  • Ориентироваться на roofline-модель.

Энергия и экономика

Оптимизация нужна не ради самой оптимизации. Она влияет на экономику: в серверных вычислениях — меньше затрат на мощности, в батарейных роботах — меньше потребление энергии.

Расчёт инференса MobileNetV4

  • Параметров сети: 1,8 млн
  • Операций умножения и сложения: 3,7 млрд
  • Скорость цикла: 10 мс
  • Запусков в секунду: 100
Энергия MobileNetV4 MobileNetV4 + ускорители
На умножение + сложение 78,8 мДж 1,06 мДж
На чтение + запись 55 мкДж 211 мкДж
Потребление, Вт·ч 7,88 0,128

Итог: экономия энергии — 61,56 раз. Энергия на чтение/запись даже немного выросла, но это с лихвой компенсируется падением энергии на сами вычисления.

Масштабирование на GPT-4

  • Стоимость содержания: 83 000 000 руб.
  • Экономия в год: 80 800 000 руб.

В батарейных роботах это часы дополнительной автономной работы, в облаке — миллионы сэкономленных рублей.

Чего не хватает в C++20

1. Раздувание кода из-за шаблонов

Каждая инстанциация шаблона порождает новый код. При слишком детальной архитектуре прошивка растёт экспоненциально. Решение — ограничивать число модулей и следить за размером бинарника.

2. Отсутствие рефлексии

В C++20 нет встроенной рефлексии — программа не может «посмотреть на саму себя». Это мешает сериализации, логированию и обработке ошибок. Ожидается в C++26.

3. Прагма MBED

Её ждут, но полноценной замены пока нет. Сейчас используются внешние скрипты, вставляющие бинарные функции в HEX-формате в код.

4. Логи и принты

В прошивке на 2 МБ около 40% кода — это текст логов и сообщений. Решение: вынести текст ошибок в Doxygen-комментарии и внешний JSON, а в бинарнике хранить только код ошибки.

5. Обработка ошибок

Исключения плохо подходят для систем, которые работают непрерывно. Спикер рекомендует boost::expected — контейнер, хранящий либо значение, либо ошибку.

Код: boost::expected

boost::expected<int, Error> read_sensor() {
    if (!sensor.ready()) return boost::unexpected(Error::NotReady);
    return sensor.value();
}

Выводы

  • C++20 в embedded — инструмент для абстракций с нулевой стоимостью.
  • constexpr и шаблоны переносят вычисления на этап компиляции.
  • Статическое связывание даёт детерминизм и ускорение до 12 раз.
  • Для GeMM важны кэш, SIMD и OpenMP.
  • Оптимизация влияет на энергию: экономия до 61,56 раза на MobileNetV4 и до 80,8 млн руб. в год на GPT-4.
  • C++20 не хватает рефлексии и прагмы MBED, а логи занимают до 40% прошивки.
  • Для постоянных систем лучше подходит boost::expected, чем исключения.
  • КИХ-фильтры предпочтительнее БИХ из-за устойчивости и аппаратной поддержки.
  • Будущее — комбинация современных абстракций и понимания аппаратных ограничений.

Глоссарий

  • Zero-cost abstractions — абстракции без накладных расходов.
  • RAII — управление ресурсами через конструкторы и деструкторы.
  • Jitter — разброс времени отклика системы.
  • DMA — прямой доступ к памяти без участия CPU.
  • MMU — модуль управления виртуальной памятью.
  • SIMD, NEON, MVE, AVX — векторные расширения процессоров.
  • OpenMP — многопоточные вычисления.
  • GeMM — обобщённое матричное умножение.
  • RTPS, DDS, Micro XRCE-DDS — протоколы обмена сообщениями.
  • NPU — нейронный ускоритель.
  • BLDC — бесколлекторный двигатель постоянного тока.
  • MISRA, AUTOSAR — стандарты безопасного embedded-кода.
  • LUT — таблица подстановки.
  • FIR/IIR — фильтры с конечной и бесконечной импульсной характеристикой.
  • boost::expected — контейнер «значение или ошибка».
  • Core Coupled Memory — быстрая память, похожая на кэш L1.
  • nano libc — облегчённая стандартная библиотека C для МК.
  • ETL — Embedded Template Library.
  • Eigen — библиотека линейной алгебры.
